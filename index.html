Why APSOC

安全产品越买越多，问题却没有变少

企业安全建设长期困在「烟囱式堆叠」里：每个产品一套 Agent、一个控制台、一种数据格式，彼此割裂、重复建设。

PROBLEM / 01

重复采集，资源浪费

EDR、DLP、日志、资产各自部署 Agent，同一份主机数据被采集多遍，终端越来越卡，运维疲于奔命。

PROBLEM / 02

数据割裂，难以关联

告警散落在不同平台，攻击横跨网络、终端、数据多个环节时，无法串成完整链路，研判靠人肉、溯源靠运气。

PROBLEM / 03

能力封闭，无法扩展

商业安全产品能力固化、接口封闭，新威胁来了只能等厂商升级，企业无法在统一底座上自主扩展。

Core Concept

把安全能力拆成原子，按需编排复用

APSOC 将平台能力解耦为三类原子件，通过统一数据总线与策略引擎编排，从根本上杜绝重复建设。

采集点 Sensor

网络探针、终端 Agent、全流量——一次采集，数据可被任意分析能力订阅。

分析能力 Analyzer

NDR、DLP、主机安全、漏洞、情报——同一数据多处分析，不再重复采集。

执行点 Enforcer

WAF、防火墙、Agent——一个分析结果，可在最恰当的位置多点执行阻断。

DESIGN RULES
一次采集，多处分析；
一个结果，多点执行。
  • 探针可同时探测数据安全与威胁
  • WAF 可作为数据外泄的阻断点
  • DLP 主机监测可上报主机安全信号
  • 全流量同时支撑取证与合规审计
  • 终端侧只部署一个 Agent
Architecture

分层架构，内核稳定而能力可生长

基座保持小而稳定，所有安全能力以插件形式运行；标准化接入框架同时纳管第三方设备。

Plugin Matrix

持续扩展的插件生态

每一个能力都是基座上可热插拔的插件，按优先级分阶段交付，并向社区开发者开放。

P0

资产探测 / CMDB

主动 + 被动资产发现，影子资产识别，资产指纹、暴露面与责任人统一入库。

P0

漏洞扫描 / 情报

主机、Web、容器全覆盖扫描，结合 CVE/CNVD 情报与资产关联做风险优先级。

P0

全流量 / NDR

全流量留存与回溯取证，网络侧威胁检测、IOC 匹配与攻击链还原。

P0

SIEM / 统一控制台

统一告警中心、跨域事件关联、日志审计与等保合规报表，一个后端管所有。

P1

EDR / 终端基座

终端 EDR + DLP + 日志 + 应急响应辅助，一个 Agent 承载全部终端能力。

P1

DLP / 数据安全

数据分类分级、全流程追踪与外泄阻断；采集与执行复用探针、WAF 与 Agent。

P1

蜜罐 / 欺骗防御

高交互蜜罐、蜜标蜜账，主动诱捕攻击者，告警接入统一数据总线。

P1

WAF / 防火墙

L7 与 L3-L4 防护与阻断，同时作为 DLP、情报与 SOAR 的统一执行点。

P1

威胁情报 TIP

本地化情报库与 IOC 匹配，遥测数据反哺情报，形成数据飞轮。

AI SOC

让 AI 承担重复研判，让人做决策

AI 不是噱头，而是嵌入运营流程的生产力；所有自动动作受控、可审计、人在回路。

AI TRIAGE

智能告警研判

告警自动关联降噪、ATT&CK 映射、攻击链串联，给出带证据的研判结论。

  • 告警聚合，减少 90% 噪声
  • 证据接地，结论可追溯
  • 自然语言交互式调查
FULL TRAFFIC

攻击全流量回溯

全流量留存，任何事件都可回到原始 PCAP 完整还原攻击过程并取证。

  • 事件一键定位原始流量
  • 攻击回放与证据导出
  • 支撑 NDR / DLP / 合规
CONTROLLED ACTION

受控自动响应

SOAR 剧本按风险分级执行，高危动作必须人工审批，全程审计可回滚。

  • 动作风险五级 + 三级审批
  • 低风险动作自动处置
  • AI 不越权、不盲动
Roadmap

基座先行，能力持续上架

先证明基座可扩展，再让所有能力以插件形式持续交付，而非一次性堆砌。

统一数据湖、控制台、采集驱动，交付资产、漏扫、全流量、NDR、日志合规插件。

P1 · 15–24 月

插件市场 + AI 运营

插件市场上线，EDR、DLP、蜜罐、WAF、情报、SOAR、AI 副驾陆续上架。

P2 · 24 月+

开放生态

第三方插件生态繁荣（目标占比 ≥30%），情报订阅、安全服务与培训体系成熟。
